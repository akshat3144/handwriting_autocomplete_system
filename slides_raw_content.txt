Interesting things implemented from the guide
Weight Tying (Parameter Sharing)
The Input Embedding layer (tokens -> vectors) and the Output Head
(vectors -> probabilities) share the exact same weights.
Why It Matters
Semantic Logic: The vector representation for "cat" at the input should
be the same target vector used to predict "cat" at the output.
Massive Efficiency:
The embedding table is huge (50,257 x 768).
Sharing this saves ~38 million parameters.
Reduces total model size by ~30%.

Residual Stream Initialization
The Challenge: Variance Explosion
Residual connections follow the formula: xl+1
=xl
+ f(xl ).
Because we keep adding to the signal, the variance of activations
grows drastically as the network gets deeper, leading to instability.
The Solution: 1/2N Scaling (Similar to that in UDL!!)
Scale the weights of residual layers by 1/2N (where N is the
number of layers).
The Outcome
Counteracts the growth caused by summation.
Keeps the variance of the output roughly 1.0 from start to finish.
"clean" signal propagation and stable training.

Interesting things implemented from the guide
The "Ugly Numbers" Optimization
Original GPT-2 vocab size is 50,257. This number is prime and odd.
GPUs struggle with this; they prefer powers of 2 (32, 64, 128) to avoid
inefficient boundary checks.
The Fix: Pad to 50,304
Artificially increase vocab size to 50,304.
50,304 is divisible by 128, allowing CUDA kernels to fully saturate
hardware.
The Counter-Intuitive Result
~4% Speedup in training.
Even though we added more parameters (fake tokens), the GPU
runs significantly faster because the math aligns with the hardware
architecture.
